# Editor & Envelope-Reader Redesign

**Date:** 2026-06-03
**Author:** Rafa (with scribe)
**Lens:** UX product engineering + HCI, walked through the equanimitech
pyramid (Sovereignty → Awareness → Equanimity).
**Status:** Design spec. Implementation deferred to a later session.

> **Scoping note.** The clarifying fork (distinct reader vs. unified surface;
> spec vs. build) went unanswered, so this spec takes the equanimitech-sound
> default: **keep one document, split it into two explicit** _**intents**_ **—
> Compose and Attend — with the seal as the hinge between them.** Deliverable
> is this spec only; no code lands tonight.

***

## TL;DR (5-second scan)

Today the editor and the read view are **one undifferentiated surface**: a
Crepe WYSIWYG body, a flickering "Saving…" label, an amber stamp button in the
footer corner, and frontmatter hidden behind an offcanvas toggle. Reading a
sealed decision to _rely on it_ and composing a draft happen in the same
chrome — so the most consequential act in the product (the stamp) is a 28px
corner button, and the trust model (signature / stamp / verify) is invisible.

**The redesign introduces two intents over one document:**

| <br />   | **Compose** (edit)                 | **Attend** (read / verify)     |
| -------- | ---------------------------------- | ------------------------------ |
| Goal     | get the words right                | decide whether to trust / seal |
| Chrome   | editing affordances, calm autosave | provenance-forward, zoomable   |
| Seal     | "ready to seal" hint               | the ceremony lives here        |
| Friction | low (writing is fluid)             | deliberate (sealing is sober)  |

The **seal is the hinge** — sober, not a caution-amber warning. Verify state
becomes first-class. Save becomes ambient. Editing a sealed doc surfaces a
calm "this breaks the seal" boundary instead of silently invalidating it.

***

## Problem (current-state diagnosis)

`MarkdownWindow` is the single orchestrator: `MarkdownTitlebar` + a scrollable
`CrepeEditor` + `EnvelopeFooter` (stamp button / stamped pill) + an offcanvas
`FrontmatterPanel`. HCI / equanimitech faults:

1. **No intent distinction.** Reading-for-trust and editing-for-composition
   are different jobs with different attentional postures, collapsed into one
   surface. _Downstream Allocation_ fails: the system never signals "you are
   now in authoritative-record territory."
2. **Inverted friction.** Editing is frictionless; the weighty intentional act
   (stamp) is a corner button. Equanimitech wants the **intentional** path
   clear and the careless path resisted. Here it's reversed.
3. **Amber = wrong semantics.** The stamped pill is amber — amber reads
   _caution / warning_. A seal is an _achievement of trust_, not a hazard.
4. **No verify surface.** AGENTS.md hard rule #5 ("verify before trusting")
   and the three-layer model (signature mandatory · stamp selective ·
   counter-stamp reserved) are **entirely invisible**. The reader cannot tell
   signed-only (informational) from stamped (authoritative) from tampered
   (quarantine). `EnvelopeFooter` shows stamp state only — never signature or
   verify results.
5. **Anxious save.** "Saving…" text flickers on an 800ms debounce over a 500ms
   poll. _Peripheral Presence_ violated — status should be ambient and
   ignorable, not focal churn.
6. **Frontmatter relegated.** For a markdown-in-git substrate, frontmatter
   (`$type`, dates, `authorized_agents`) is part of _reading the document's
   nature_, yet it's hidden behind a toggle.
7. **Silent seal-breaking.** Nothing stops the principal editing a sealed doc
   and invalidating the attestation without warning.

***

## Design — generated by walking the pyramid

### Foundation · Sovereignty

* **Local-First Ownership** — pass, and the redesign must _stay_ pass: no
  network affordance, no telemetry, no "sync" status that implies a server.
  The ambient save dot reflects **disk**, never a cloud. ✓

* **Holistic Control** — every chrome element self-explains. The seal is
  inspectable: hovering it explains the three trust layers in plain language,
  not jargon. Each mode is disable-free — Attend is not a paywall on editing,
  just a posture you can leave with one key.

* **Modification Rights** — keep "Reveal in Finder"; **add an "Edit raw"
  escape hatch** (open the underlying `.md` in the system editor) so the
  principal is never trapped in Crepe. A non-technical user can freeze the doc
  simply by not sealing — it's a plain file.

### Practice · Awareness

* **Bounded Experiences** — both intents get a natural end. Attend ends in a
  decision (seal, or leave). Compose ends in "ready." Replace dead end-of-body
  scroll with a quiet end-marker (e.g. a centered hairline + the doc's
  trust-state restated), **never** an autoplay "next document." If the
  principal stops, that's success, not churn.

* **Peripheral Presence** — the "Saving…" label becomes a single ambient
  glyph in the title bar: calm when synced, a slow (not anxious) pulse while
  writing. Ignorable for hours; legible in a glance. No toast on every save.

* **Attentional Granularity** (content depth, _not_ chrome disclosure) — the
  provenance surface is **zoomable in three rungs**:

  * **Coarse** — one trust chip: _Sealed · Signed · Unsigned · ⚠ Tampered_.

  * **Medium** — who sealed, when; signer; frontmatter type.

  * **Fine** — signature hex, doc-hash preimage, full `sec verify --json`
    trace, counter-stamp slots.
    The reader descends only as far as their attention goes.

### Outcome · Equanimity

* **Strategic Friction** — make read-fully-then-seal the clear path and
  seal-blind / edit-a-sealed-doc the resisted one. Concretely: the stamp
  ceremony lives in **Attend** mode (you're already reading); editing a sealed
  doc triggers a calm interstitial — _"Editing breaks the current seal. The
  record reverts to signed-only until you re-stamp."_ — not silent
  invalidation. _Construct: Non-reactivity (ES-16)_ — widen the gap between
  impulse and act.

* **Fade-by-Design** — **no stamp count, no streak, no "X sealed this week."**
  Gamifying the seal would couple it to hedonic reward — the exact
  anti-pattern. The seal stays sober. Success is the principal sealing _less
  but better_ — exactly AGENTS.md's "stamp is selective, not mandatory."
  _Construct: Hedonic Independence (EQUA-S)._ The tool makes the principal more
  discerning, not more dependent.

* **Downstream Allocation** — mode is principal-chosen; the system never
  queues "next to stamp," never notifies, never auto-advances. The principal
  owns what they look at. _Construct: Decoupling Model._ ✓ (matches the
  no-notifications / anti-compulsion stance and the review-session model.)

## The two intents, drawn

### Compose mode (editor)

```
┌────────────────────────────────────────────────────────────┐
│ ◴  2026-06-01 signet-boundary        ·decision·   ● synced  │  ← title bar:
│                                            [Attend ⇥] [raw] [⌘K] │    doc title,
├────────────────────────────────────────────────────────────┤    type chip,
│                                                              │    ambient save
│   # Signet ↔ Secretariat boundary                            │    dot, mode
│                                                              │    toggle, raw
│   Signet is the trust primitive…                             │    escape, palette
│   (Crepe WYSIWYG body — fluid, low-friction)                 │
│                                                              │
│                                                              │
│                  · · · end of document · · ·                 │  ← bounded end,
│                  signed-only — not yet sealed                │    restates trust
├────────────────────────────────────────────────────────────┤
│  Frontmatter ▸ type: decision · $type: …stamp · 2 agents    │  ← inline, legible
└────────────────────────────────────────────────────────────┘    (expand = panel)
```

Notes:

* **Frontmatter inline, collapsed** at the foot of the body — a one-line
  legible summary that expands to the full field editor. No more hidden
  offcanvas as the only access.

* **No stamp button here.** Compose hints "ready to seal? → Attend" but the
  ceremony belongs in the reading posture.

* Ambient `● synced` dot replaces "Saving…".

### Attend mode (envelope reader / verify)

```
┌────────────────────────────────────────────────────────────┐
│ ◴  2026-06-01 signet-boundary        ·decision·  [Compose ⇥]│
├────────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────────┐  │
│  │  ✓ SEALED by you · 2026-06-01            [details ▾]   │  │  ← trust banner,
│  │    signature verified · doc hash matches               │  │    coarse rung.
│  └──────────────────────────────────────────────────────┘  │    Sober, not amber.
│                                                              │    Expands ↓
│   # Signet ↔ Secretariat boundary                            │
│   (read-optimized typography; not editable in place)         │
│   …                                                          │
│                                                              │
│                  · · · you have read to the end · · ·        │  ← bounded end =
│                  [ Seal this document ]   (if unsealed)      │    where ceremony
└────────────────────────────────────────────────────────────┘    becomes available
```

`[details ▾]` expands the **medium → fine** provenance rungs:

```
   Trust layers
   ─────────────────────────────────────────────
   Signature   ✓ verified   did:key:z6Mk… (you)
   Stamp       ✓ sealed      2026-06-01 14:22
   Counter     — none (reserved)
   ─────────────────────────────────────────────
   ▸ doc hash   sha256:9f3a…           (matches)
   ▸ signature  ed25519:7c1b…
   ▸ raw verify { "signature": "ok", … }   ⧉ copy
```

The ceremony itself is unchanged in protocol (read full body → explicit
consent → Touch ID gate). The redesign only relocates and re-weights it:
it now happens **where the principal is already reading the full body**, which
makes hard-rule-#4 step 2 ("render the full body verbatim") the _natural_ state
rather than a separate render.

## Trust-state vocabulary (the coarse chip)

One chip, four states, sober palette — never caution-amber for a good seal:

| State        | Glyph · color     | Meaning                                           | Action surfaced                                         |
| ------------ | ----------------- | ------------------------------------------------- | ------------------------------------------------------- |
| **Sealed**   | ✓ · deep teal/ink | signature verified **and** stamped                | view provenance                                         |
| **Signed**   | ◷ · neutral slate | signature verified, not stamped — _informational_ | offer Seal                                              |
| **Unsigned** | ○ · muted         | no detached signature yet                         | (compose)                                               |
| **Tampered** | ⚠ · red           | signature fails / hash mismatch                   | quarantine — body dimmed, edit blocked until re-derived |

This makes AGENTS.md rule #5 a UI invariant: a failed-signature doc is
**quarantined** (dimmed, not silently surfaced), satisfying "malformed →
quarantine, not surface."

## Four-layer diagnostic (post-generation check)

* **Convivial Infrastructure (Illich)** — pass. Everything is local files +
  `sec verify`; no server, offline-complete. The save dot must reflect disk
  only.

* **Holistic Production (Franklin) — checked hardest.** The redesign builds
  the principal's _judgment_: the provenance rungs teach what a seal means; the
  break-the-seal interstitial makes the consequence legible; the absence of
  gamification keeps sealing a considered act. It does not merely block or
  decorate — it makes the trust model _inspectable and learnable_. Pass, **if**
  the `[details ▾]` copy is plain-language, not lexicon jargon. ← acceptance gate.

* **Attentive Consumption** — pass. Peripheral save, principal-allocated mode,
  no auto-advance, friction on the careless path.

* **Calm Interface (Weiser/Case)** — pass. Ambient save glyph, graceful
  tamper-failure (quarantine, not crash), modality matches (read vs. write).

## Washing-check

* Gamified equanimity score? **No** — explicitly no stamp count/streak.

* Wellbeing theater on an engagement product? **No** — no engagement parent.

* Fade = planned obsolescence? **No** — the _user_ becomes more discerning;
  the tool persists as a workshop tool, not a crutch that retires the user.

* Indifference as equanimity (near enemy)? **Guarded** — the sober seal is
  _careful attention_, not "I don't care." The break-the-seal interstitial
  expresses care for the record's integrity.

* Manifesto-coated mediocrity? Guard the `[details ▾]` plain-language gate; if
  it ships as raw hex with no explanation, it's washing.

## Measurement constraint

This design creates _structural conditions_ mapped to **Non-reactivity
(ES-16)**, **Hedonic Independence (EQUA-S)**, and the **Decoupling Model**. It
does **not** produce equanimity, and no instrument has been applied to
technology design interventions. These mappings are a **design hypothesis, not
validated.** Do not claim the redesign cultivates equanimity — claim it widens
the gap where the principal's choice lives.

## Scope (Shape-Up tiers)

**Must-have (the bet):**

1. Two intents over one document (`Compose` / `Attend`), one-key toggle.
2. Trust-state chip + banner with the four-state vocabulary; verify wired
   (`sec verify --json` → new Tauri binding) so signature state is real, not
   stamp-only.
3. Sober seal (retire amber-as-good); ceremony relocated to Attend's bounded
   end; protocol unchanged.
4. Break-the-seal interstitial on editing a sealed doc.

**Should-have:**
5\. Ambient save glyph replacing "Saving…".
6\. Zoomable provenance (coarse → medium → fine rungs).
7\. Inline collapsed frontmatter summary (expand to full panel).

**Nice-to-have:**
8\. "Edit raw" escape hatch.
9\. Bounded end-of-document marker.
10\. Tamper quarantine visual (dim + edit-block).

## Open questions / risks

* **Verify binding.** Front-end has `stampEnvelope`, `readMarkdown`, etc., but
  no `verifyEnvelope` binding surfaced. Must-have #2 depends on adding it
  (`crates/cli` already does `sec verify --json` → `{signature, stamp,
  counter_stamps}`). Confirm the binding before committing to the trust banner.

* **Mode toggle vs. two windows.** Toggle within one `MarkdownWindow` (state)
  vs. distinct webview routes. Recommend in-component state to preserve
  scroll/identity context and keep it one file's responsibility.

* **Crepe read-mode.** Attend wants read-optimized, non-editable typography.
  Either a read-only Crepe config or a separate renderer. Decide in plan.

* **Counter-stamp slot** is reserved (no record type ships) — render as a
  greyed "reserved" row, not a live affordance.
