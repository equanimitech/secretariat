## Decision (2026-05-18)

Three coupled changes — bundle, don't ship piecemeal.

### 1. Schema-aware frontmatter (sidebar)

Today `FrontmatterPanel` iterates top-level YAML keys and infers control
from JS type. For envelopes (nested `$envelope:` / `$attestation:`) it
sees two keys, both objects, both fall to `nested` → readonly JSON dump.
Editor is unusable for the most common case.

Fix: dispatch on the `$type` discriminator inside the nested block.
Hand-curated TS table at `src/lib/markdown/schemas.ts` mapping each
known `$type` to field descriptors `{key, control, editable, enumValues,
description}`. Lexicons remain authoritative on disk (rule #3); the TS
table accumulates by practice. Unknown `$type` → fall back to today's
inference.

Editable matrix (seven types seen on disk):

| `$type`         | editable                                                                   | frozen                                                                           |
| --------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| envelope        | depth (enum), urgency (enum), source, cadenceHint, replyTo                 | from, to, handle                                                                 |
| attestation     | —                                                                          | signer, act, docHash, docFilename, stampedAt, signature                          |
| channelDef      | name, description, visibility (enum), relayHint, retiredAt                 | handle, creator, createdAt                                                       |
| channelContract | cadence\_floor\_minutes, min\_trust, root\_path, launch\_args, launch\_env | —                                                                                |
| identity        | display\_name, full\_name                                                  | did, did\_method, key\_path, key\_type, key\_\*\_at, key\_rotations, created\_at |
| contact         | display\_name, full\_name, relay\_endpoint                                 | did, added\_at                                                                   |
| org             | name, description                                                          | alias, did, created\_at                                                          |
| rosterUpdate    | note                                                                       | signer, op, subject, channel, roles, effectiveAt, signature                      |

### 2. Attestation strip (not chip, not footer — strip)

One row between titlebar and editor body, conditional on `$attestation`:

```
✕ stamped · Rafa · 2026-05-17 14:23Z · did:key:z6M…sfak · ✓
```

* Subtle amber tone (wax-seal warmth, not security-green — this is
  weight, not validation status).

* Slots: act verb (`stamped` / future `deferred` / `vouched` / `disputed`
  / `redirected` per lexicon reserved values) · signer display name
  resolved against `contacts.md` / `identity.md` · `stampedAt` formatted
  `YYYY-MM-DD HH:mmZ` · truncated DID in monospace (hover full, click
  copy) · trailing ✓/✕ from `sec verify --json`.

* Raw `signature` + `docHash` move to a collapsed "Attestation" group in
  the sidebar (readonly monospace, copy buttons).

* Single delight: when a stamp lands, the strip slides in from above
  (60ms ease-out). Otherwise static — system fonts, neutral chrome.

### 3. Sidebar resizable

Today fixed `SIDEBAR_WIDTH = '16rem'`. DIDs need 24rem+. Drag handle on
inner edge of right sidebar; width persisted to `localStorage` under
`secretariat.markdown.sidebarWidth`. Bounds `18rem ≤ width ≤ 36rem`,
default `22rem`. shadcn `Sidebar` already drives `--sidebar-width` —
write the CSS var, don't fork the primitive.

### Cuts / followups

* Identity / contact / org / rosterUpdate edit paths land via the schema
  table but aren't exercised yet (editor doesn't open those files in
  practice today). They light up automatically when it does.

* `sec verify --json` wire-up for ✓/✕ is the existing followup at
  `docs/superpowers/specs/2026-05-17-markdown-reader-followups.md` —
  blocks the live icon but not the strip itself.

* Lexicon JSON not loaded at runtime. Codegen from `lexicons/` waits for
  a second implementation (rule #3, practice-is-the-gate).

### Out of scope

* Editing `$attestation` fields — cryptographically frozen.

* Editing `from` / `to` / `handle` — pin queue identity; mutation
  requires re-signing and belongs to the daemon, not the principal.
